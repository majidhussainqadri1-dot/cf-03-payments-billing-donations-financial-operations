CF-03 already defined invoices, receipts and secure finance exports, but it did not expose one explicit, versioned financial-download contract across source, routes, manifests and regression tests.

This amendment adds:

- `CF03-FR-043 — Eligible Financial Asset Download`;

- no live-delivery implementation or provider bypass.

## CF03-FR-043 — Eligible Financial Asset Download

Eligible CF-03 financial assets are:

- owner-scoped invoice snapshots;
- owner-scoped donation/payment receipts;
- requester/authorized-finance scoped secure export artifacts;
- verified aggregate public transparency snapshots.

The native CF-03 owner must decide eligibility and current authorization. File 20 may manage global download progress and File 25 may render the control, but neither may infer financial ownership, alter the ledger or manufacture download permission.

A grant must include a stable asset reference, safe filename, approved media type, SHA-256 checksum, audience, policy version, creation/expiry timestamps and an approved opaque or vault-scoped delivery reference. Restricted, expired, revoked, not-ready, privacy-restricted or unauthorized assets must be hidden or denied with a stable reason and without exposing a delivery reference.

## Presentation boundary

The semantic presentation contract requires:

- visible text label `Download`;
- Ionicons icon `download-outline`;
- platform primary green token;
- keyboard, screen-reader and RTL support through File 25;
- no CF-03-owned duplicate theme, shell or Global Download Manager.

Operational acceptance still requires Hostinger staging, File 20/File 25 integration, File 24 assurance, CF-04 or approved same-origin secure delivery, browser/accessibility testing, backup/restore/rollback and explicit Founder approval.
